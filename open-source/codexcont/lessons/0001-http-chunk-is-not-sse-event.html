HTTP chunk 不是 SSE event

任务：读懂 incremental_sse()，并能解释它为何是 fold_stream() 的必要基础。

与你的任务的关系。你想安全运行并理解 CodexCont。只要把“网络本次给我的字节”误认为“模型发来的一条完整事件”，代理就会在真实网络下随机解析失败。今天只学会一个边界：chunk 是运输单位；SSE event 是协议单位。

1. 先用一个反例建立直觉

假设上游的一条 SSE event 在文本上长这样：

event: response.output_text.delta
data: {"type":"response.output_text.delta","delta":"你好"}

网络可以把它交给程序的方式完全不同：

情况aiter_bytes() 看到的 chunk是否已经是完整 event？
A整段文本一次到达碰巧是
Bevent: ...\ndata: {"type":"res，然后其余文本不是
C每次只到一个或几个字节不是

如果程序对每个 chunk 直接执行 json.loads(chunk)，B 和 C 会失败。这个失败不是模型错了，而是程序在错误的边界上解析。

2. 项目怎样把边界找回来

打开源码：middleware/sse.py。下面是 incremental_sse() 的核心，不是伪代码：

buffer = b""
data_lines: list[str] = []

async for chunk in byte_iter:
    buffer += chunk
    while b"\n" in buffer:
        raw, buffer = buffer.split(b"\n", 1)
        line = _decode_line(raw)

        if line == "":
            ev = flush_event()
            if ev is not None:
                yield DONE if ev[0] == "done" else ev[1]
            continue
        if line.startswith(":"):
            continue
        if line.startswith("data:"):
            data_lines.append(...)
代码对象它保存什么为什么需要它
buffer还没有出现换行的残余字节某一行可能被网络切成两段。
data_lines当前 SSE event 的所有 data: 行一个 SSE event 可以含多个 data 行。
空行 ""event 结束信号这才是调用 flush_event() 的时机。
yield一个已解析 event 或 DONE让下游可以立即处理，不用等完整 response。

3. 手推一次真实变量变化

把同一条 event 人为分成三块：

chunk 1: b'event: x\ndata: {"type":"x","delta":"'
chunk 2: b'你好"}\n'
chunk 3: b'\n'
  1. chunk 1：buffer 能取出 event: x 和未完成的 data: 行；后者进入 data_lines。没有空行，所以不 yield。
  2. chunk 2：完成 data 行；仍没有空行，所以仍不 yield。
  3. chunk 3：读到空行；flush_event() 拼接 data_lines、解析 JSON，并 yield 一个 dict。
关键结论：程序不会“等待整个 response”；它只等待当前 event 的结束边界。这就是流式与正确解析可以同时成立的原因。

4. 它怎样接到 fold_stream()

middleware/proxy.py 不直接处理 bytes，而是：

byte_src = response.aiter_bytes()
async for ev in incremental_sse(byte_src):
    if ev is DONE:
        saw_done = True
        continue
    # ev 现在是完整的 dict，才能根据 ev["type"] 做状态机分支

因此分工是：

  • incremental_sse()：负责把不可靠的字节分块变成可靠的协议事件。
  • fold_stream()：负责根据事件类型决定 reasoning 立即下发、message 缓冲还是结束 response。

不要在 fold_stream() 里修网络分帧，也不要在 sse.py 里做续写业务判断。这是当前模块边界。

5. 检索练习：先回答，再展开答案

练习 A

上游已经发送一个完整 JSON，但还没发送 SSE 的空行。incremental_sse() 应不应该 yield？为什么？

查看反馈

不应该。在本项目里空行才结束一个 SSE event。JSON 看起来完整不等于协议 event 已结束；程序必须尊重 framing。

练习 B

为什么 DONE 在 fold_stream() 中只设置 saw_done，而不是立刻 return？

查看反馈

因为 [DONE] 不是业务 terminal response。代理还要依赖 response.completed、response.failed 或 response.incomplete 来决定是否 flush 暂定输出、续写，或合成 incomplete。

练习 C

若你把 incremental_sse() 改成“每个 chunk 都解析一次 JSON”，哪一项现有测试最应该失败？

查看反馈

test_sse_framing()。它把 fixture 用不同 chunk size 切开，并断言事件数量与类型保持一致。
