# `.gitignore`：把本地秘密和运行产物留在工作区外

**源码路径：** [`../../.gitignore`](../../.gitignore)
**核对日期：** 2026-07-14
**总览：** [返回项目学习总览](../CODEXCONT_LEARNING_GUIDE_zh.md)

这不是运行代码，但它维护一个重要安全边界：哪些本机文件不应被 Git 纳入版本控制。

## 规则与项目关系

- Python 缓存、测试/类型检查缓存与 `*.egg-info`：可再生成，不是源码事实。
- `.venv/`：本机安装的第三方依赖，不应与项目源码混淆；这也是逐文件学习不覆盖它的原因。
- IDE/系统目录：开发者机器状态，不应制造无意义差异。
- `config.toml`、`rt.json`、`free_rt.json`：可能包含本机上游、认证或运行状态；尤其 `config.toml` 才是 `run.py` 真正读取的文件，必须保持不提交。

## 不能保证什么

`.gitignore` 只能阻止**尚未被追踪**的文件自动出现于 Git 状态；若敏感文件过去已提交，新增忽略规则不会从历史或索引删除它。也不能替代 token 轮换、访问控制或审查。配置模板 `config.example.toml` 应保持无秘密，供安全复制。

**验证：** 用 `git status --ignored` 查看规则效果；执行前不要把该命令输出中的真实配置内容粘贴到公共位置。
