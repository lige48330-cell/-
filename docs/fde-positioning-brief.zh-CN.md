# FDE 求职交付 brief

## 目标

把作品集、简历和 GitHub 入口统一成一个招聘可读的定位：

> FDE / Forward Deployed Engineer：从业务现场出发，把复杂问题推进成可运行、可验证、可交接的系统。

## 不再使用的主叙事

- AI 辅助全栈工程师
- 只按技术栈罗列项目
- 只展示页面，不说明现场问题、个人边界和验证方式
- 夸张的“全链路”“主导”“平台已上线”等无证据表述

## 证据结构

| 层级 | 招聘方要看到什么 | 当前载体 |
| --- | --- | --- |
| 5 秒 | 身份、问题域、交付结果 | 首页首屏 / 简历标题 |
| 30 秒 | 交付链与核心案例 | FDE 交付链 / ERP、IoT、桌面端案例 |
| 2 分钟 | 个人边界、工程方法、验证证据 | Case study、Agent 工程、项目索引 |
| 深读 | 源码、测试、脱敏截图、方案文档 | GitHub 公开工程与面试说明 |

## 核心交付链

现场理解 → 问题建模 → 原型验证 → 系统集成 → 联调验收 → 团队交接

## 主案例排序

1. 养殖渔业 ERP：业务建模、字段状态、低代码配置与关键闭环验证。
2. 养殖场 IoT / 小程序：设备状态、事件、预警、管理视图与端云协同边界。
3. Cockpit Tools：Tauri + React + Rust 私有化桌面工程、配置边界、provider runtime 与回归验证。

## 简历交付物

- `resume.html`：可编辑、可打印、适合投递的中文 FDE 简历。
- `candidate-resume.zh-CN.md`：事实母稿，便于后续补充真实姓名、邮箱、时间线和教育信息。
- 首页：身份、价值、交付链、核心案例、Agent 工程方法与证据索引。

## 验收标准

- 首屏第一句明确是 FDE，而不是把 AI 放在职位名称前。
- 每个主案例都能回答：现场问题、我的边界、交付物、验证方式。
- 公司项目只展示 AI 辅助脱敏截图、方法和职责，不公开源码、账号、配置或真实业务数据。
- 个人项目能跳转到源码或项目说明。
- 简历可以直接打印为 A4，不依赖截图，不使用无法证明的量化结果。
