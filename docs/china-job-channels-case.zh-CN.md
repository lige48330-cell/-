# China Job Channels · 有界求职运营工作台

> PROJECT 04 / LOCAL BUILD / DATA OPERATIONS

## 一句话

把一个依赖浏览器登录态、第三方页面和人工判断的求职运营问题，收敛成一条可检查、可恢复、可交接的全栈数据链。

## 系统触点

- 策略边界：城市、岗位、薪资、经验、正式全职和批次上限先成为显式约束。
- Node 本地 Dashboard：提供会话启动、记录接收、状态分层和静态预览入口。
- Python 采集器：处理受控的浏览器采集和离线解析，保留详情上下文。
- 规范化层：把原始结果收敛为稳定 JSONL 结构，保留来源、时间和状态。
- 记录真源：区分 `sent`、`clicked`、`failed` 和 `skipped_qualification`，避免把一次点击误报为完成。
- 验证：`npm run check` 覆盖 JavaScript smoke / E2E、接口、规范化和 Python 离线测试。

## 我的 FDE 推进动作

1. 先把“自动沟通”拆成可审批的输入、执行、结果和恢复面。
2. 用状态机和 JSONL 契约隔开浏览器动作、数据处理和运营视图。
3. 把失败原因、记录来源和启动前提写进交接材料，让团队能继续维护。

## 可核对结果

- 本机离线检查通过：JavaScript smoke / E2E 与 Python 测试合计 57 个用例。
- 派生产物由唯一 records 入口刷新：只有确认的 `sent` 才进入已确认列表和预览。
- 批次、扫描范围和结果状态都有上限；实时浏览器行为仍需要人工受控验证。

## FDE 价值

我关注的不是“自动点得多快”，而是把输入、状态、来源、失败和恢复路径做成团队能接手的协议。这类经验可以迁移到 Agent 工具调用、数据摄取和运营后台：Agent 可以行动，但不能跳过边界、证据和人工接管。

## 公开边界

原始工程依赖登录态和第三方页面；公开仓库只保留脱敏架构、状态契约、离线证据和职责说明，不公开账号、会话数据、运行配置或抓取结果。完整案例入口见 [China Job Channels 案例页](../projects/china-job-channels.html)。
