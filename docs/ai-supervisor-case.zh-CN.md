# AI Supervisor · 脱敏能力卡

## 一句话

把 Agent 的“已完成”声明转成外部可检查的 spec / plan 规则、报告和进程退出码，让失败可以被阻断、复盘和交接。

## 我保留的工程信号

- `review`：读取规则、计划和工作区，生成可读报告。
- `guard`：把 PASS / NEEDS_REVIEW / ERROR 映射为稳定的 exit code，接入 CI 或任务闸门。
- `hook`：为任务结束事件提供硬 / 软模式边界。
- `doctor`：主动构造已知失败，检查监督链路是否真的覆盖目标工程。
- 规则类型：路径存在性、计划完成、禁止项和需要人工判断的语义边界。

## 可核对结果

- 本机工程离线测试：`93 passed`（以当时的本地代码与测试输出为依据）。
- CLI 层 known-failure 能稳定返回 `NEEDS_REVIEW` / 非零退出码。
- harness 是否每次真实触发、以及宿主是否尊重退出码，仍标记为 `unverified`，不把静态配置冒充自动阻断。

## FDE 价值

这不是“让模型更听话”的提示词技巧，而是把验收条件外置成团队可以阅读、运行和交接的质量门。它补足 TraceRAG 的另一侧：TraceRAG 证明 Agent 如何在运行时停下来，Supervisor 证明交付后如何被外部证据复核。

## 公开边界

原始本机工程包含安全研究、登录态和实验配置，不复制到公开目录。本页只保留能力、验证结果和未验证项，不含凭据、会话数据、内部路径或可直接操作的配置。
