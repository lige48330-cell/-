01 / PROJECT CASES

项目不是标题，是责任边界

每个案例聚焦我实际参与的工作、可展示的交付证据，以及这套能力可以迁移到什么场景。

CASE 01 · ERP / 低代码

养殖渔业 ERP 业务系统

把养殖业务的基础资料、库存、采购销售和设备相关流程，细化为可配置的模块、表单、字段、状态与校验规则。

01 · 业务问题

养殖资料、库存、采购销售与设备流程需要被拆成可追踪、可配置的业务规则。

02 · 我的边界

业务流程梳理、模块与字段设计、页面/流程配置与关键闭环验证。

03 · 技术链位置

业务对象与角色 → 模块/字段/表单 → 状态校验 → 关键单据闭环。

04 · 公开验证

脱敏大屏展示业务模块与管理视图；不公开客户数据、配置或完整源码。

能力沉淀 · 将现场业务语言转换成对象、状态、校验和可验证的系统闭环。

  • 业务建模
  • ERP 模块
  • 低代码配置
  • 闭环验证

CASE 02 · IOT / 数据看板

养殖场消毒除臭设备监管平台

面向现场设备管理，把在线状态、运行记录、换水记录、异常事件与地理分布汇总为一张可读的监管视图。

01 · 业务问题

现场管理需要从分散记录中快速判断设备在线、运行事件、异常和运营态势。

02 · 我的边界

监控指标梳理、状态与事件展示、管理界面和大屏功能联动。

03 · 技术链位置

设备状态与事件 → 服务端处理 → 在线态势、日志、告警和监管视图。

04 · 公开验证

脱敏监管大屏展示实时态势、地图、日志与异常反馈，不展示真实设备标识。

能力沉淀 · 用可观察的状态、事件与日志，把现场设备信息转为运营决策界面。

  • IoT 场景
  • 设备状态
  • 监控大屏
  • 可视化

CASE 03 · ESP32 / 小程序

养殖场消毒除臭设备联动小程序

围绕养殖场消毒除臭设备，完成小程序控制页面、云端通信与 ESP32 硬件状态反馈之间的联动链路。

01 · 业务问题

管理人员需要通过移动端了解设备、预警和养殖户概览，并进入日常管理流程。

02 · 我的边界

前端管理界面、设备状态呈现、云端接口协作与远程控制流程。

03 · 技术链位置

管理操作 → API / MQTT 协同 → ESP32 状态反馈 → 小程序管理总览。

04 · 公开验证

管理总览截图展示聚合状态与常用入口；不展示真实设备控制或设备标识。

能力沉淀 · 在端、云、管理端之间划清状态反馈与控制流程的责任边界。

  • ESP32
  • uni-app
  • MQTT / HTTP
  • 设备联动

    通过关键链路验证、记录证据并支持后续迭代。

05 / CAPABILITY DISTILLATION

项目带来的，不只是技术栈

从已核验的业务系统、设备平台、私有工程改造、AI 实验与开源适配中，提炼出可迁移的工作方法，而不是罗列工具名称。

WHAT I LEARNED

把复杂项目拆成边界清晰、可以被验证的能力单元。

每一项能力都能回到一个或多个本机项目的 README、工程清单或模块入口；涉及客户资料、账号、凭据、真实设备地址与完整源码的内容均不展示。

  • 业务系统
  • IoT / ESP32
  • 桌面端改造
  • AI / RAG
  • 安全研究
  • 自动化工作流
  1. 01

    业务抽象

    先建模，再做页面

    在养殖渔业 ERP 与设备平台中，学会先梳理对象、角色、状态、规则和关键闭环，再将它们落实到模块、字段、表单与管理界面。

    项目依据 · 养殖渔业 ERP、IoT 监管平台

  2. 02

    端云设备协同

    让状态与反馈形成闭环

    从固件状态上报、消息协议、服务端处理到小程序管理视图，理解设备系统的重点是可观察、可追踪的状态反馈，而非单点控制按钮。

    项目依据 · ESP32、.NET、uni-app、MQTT

  3. 03

    跨栈工程

    在运行时边界上组织系统

    通过桌面端私有工程改造，建立 React/Vite、Tauri/Rust 与 Go sidecar 之间的模块边界意识：每一层都应有清晰输入、输出与验证方式。

    项目依据 · Cockpit Tools 私有工程改造

  4. 04

    AI 系统设计

    让 AI 结论能回到证据

    从分层知识库和安全 RAG 实验中沉淀出资料分层、Schema、授权检索、审计记录与安全评估的组合方法，让 AI 输出保留来源与边界。

    项目依据 · AI-Native 知识库、Secure RAG Lab

  5. 05

    可靠性与安全

    把实验结论留在可复核的记录里

    在授权安全研究与模拟评估记录中，训练以日志、权限边界和复现条件判断结果，不以“看起来能用”代替验证。

    项目依据 · Secure RAG Lab、ReverseLab、量化研究记录

  6. 06

    人机协作自动化

    自动化加速，人负责最终判断

    从本地职位研究工具与开源工作流适配中，形成结构化数据、离线检查、流程去重和人工确认的实践习惯，避免把自动化误当成自动决策。

    项目依据 · 职位研究工具、Career-Ops 开源适配
