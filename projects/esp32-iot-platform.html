01 / 三端结构

从设备指令到业务页面的闭环

01

ESP32 固件

关注设备侧状态上报、控制命令、串口、NVS 配置、MQTT 或 API 对接边界。

02

.NET 8 云平台

承接认证、设备、客户、工单、报表、告警和监控大屏相关后端能力。

03

uni-app 小程序

面向安装人员、客户或运维角色，提供登录、设备查看、报表、告警和处理入口。

04

设备数据看板

把设备运行状态、告警、控制结果和业务报表整理成可观察的页面。

05

交接文档

用项目交接、API 目录、验收清单和部署说明降低后续接手成本。

02 / 业务模块

它证明我能进入设备、后端和业务流程之间的联调语境

  1. 设备管理维护设备档案、运行状态、绑定关系和控制入口。
  2. 工单流程连接客户、安装人员、设备问题和处理状态。
  3. 报表统计把设备数据和业务事件变成可查看指标。
  4. 告警中心记录异常、处理状态和运维反馈。
  5. 监控大屏面向管理视角展示设备运行、区域状态和关键指标。

03 / 当前边界

推进中项目最重要的是诚实验证，而不是包装完成度

这个案例适合展示系统联调思维：从 ESP32 固件到 .NET 8 云平台，再到 uni-app 小程序。当前最需要继续确认的是后端能否稳定启动、关键 API 是否连通、小程序登录和设备/报表/告警页面是否跑通。
