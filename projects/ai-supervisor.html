AI Supervisor

这是一个 AI 交付质量门禁工具：先写 spec 和 plan，再用 review 检查工作区状态，通过 guard、hook、doctor 和 known-failure falsification 把 AI 产出放进可验证流程。

01 / 监督流程

把 AI 输出从“看起来可以”变成“可以被检查”

01

spec

把需求约束写成可检查规则，明确必须满足、禁止出现和需要 AI 判断的内容。

02

plan

把实现任务写成 Create、Modify、Verify 等可追踪动作，减少“做了但没覆盖”的幻觉。

03

review

扫描工作区文件、关键词和计划覆盖情况，输出人类可读的质量报告。

04

guard / hook

把 review 结论转成命令行 exit code 或 harness hook，让不合格产出能被流程阻断。

05

doctor

用 known-failure falsification 检查监督器是否真的能抓住已知失败样本。

02 / 质量门禁

我不只是用 AI，还会约束 AI 产出

  1. 需求显性化先把隐含要求写进 spec，避免 AI 按错目标发挥。
  2. 计划可追踪把每个交付动作映射到文件和验证点。
  3. 结果可复核review 报告告诉人哪些规则通过、缺失或需要人工判断。
  4. 失败可阻断guard 和 hook 让流程能拒绝不合格输出。
  5. 监督可证伪doctor 用已知失败样本测试监督器是否真的有用。

03 / 边界说明

这是 AI 工具化能力的证据，不是单纯的 prompt 集合

当前项目证明的是：我能把 AI 协作拆成规则、计划、检查、门禁和复盘，而不是只依赖一次性聊天。真实 harness hook 的触发效果仍需要结合具体环境继续验证。
